Chapter 3: Back to Pointy Land

Building the C code emitter: leveraging Java's StringBuilder, compiling down to valid C source, and completing the compiler pipeline.

By choosing to target C as our emission language rather than targeting assembly or bytecode directly, we sidestep the nightmare of machine architecture variance and register allocation. We let standard C compilers (GCC, Clang) handle the machine-level heavy lifting.

Again, to prevent a cascade of compilation errors without understanding the downstream dependencies, we avoid a top-down approach and instead build out the Emitter class first.

We could write the emitter using raw String concatenation, but in Java that would allocate endless temporary objects on the heap. Using StringBuilder provides mutable, contiguous memory buffers and predictable performance.

My appreciation for Java stems from this predictability: standard library functions follow consistent naming conventions, interfaces are explicit, and refactoring is mechanically reliable. Even with small discoveries (like realizing standard error streams exist via System.err.println), Java remains remarkably readable.

Integrating the Emitter with the Parser

With the emitter ready, we return to the Parser to weave emission hooks into our grammar matchers, removing earlier debug print statements.

At its core, our compiler is translating a high-level BASIC dialect into structured C code. If that feels like an abstraction shortcut, remember that early C++ (Cfront) and Python's Cython operate on the exact same premise.

After wiring the program state within the parser, we complete the main harness for end-to-end testing. Translating statement structures between Python, Java, and C feels both surreal and spectacular.
